# ADR-003 — WhatsApp-First Interaction Model

**Date:** 2026-05-18  
**Status:** Accepted  
**Deciders:** Core team

---

## Context

Pakistan's SMB market runs on WhatsApp. Sales conversations happen in WhatsApp. Payment confirmations arrive in WhatsApp. Follow-up commitments are made in WhatsApp. Building a browser-first CRM and then adding a "WhatsApp integration" would force users to switch contexts and manually re-enter data — the exact failure mode that causes leads to be lost.

Research confirmed: Pakistan SMB users do not change their communication habits for software. The software must adapt to how they already work.

---

## Decision

**WhatsApp is the primary interaction layer, not an integration.**

Concrete implications:
1. Inbound WhatsApp messages auto-create Contacts and Leads — no manual entry required
2. Follow-up reminders and collection notices are sent via WhatsApp first (not email)
3. The browser UI is a management + reporting layer, not the primary data entry surface
4. WhatsApp message parsing is handled by the WhatsApp Engine with intent detection
5. Provider abstraction via `MessagingAdapter` ensures the core is not coupled to any specific WhatsApp API (Meta, 360dialog, Gupshup)

**Activation design consequence:** First-value event = first WhatsApp message processed + first deal stage moved. Not "user fills in 10 fields in a browser form." Target: value delivered within 10 minutes of onboarding.

---

## Consequences

**Positive:**
- Zero friction adoption — users continue using WhatsApp exactly as they do today
- Auto-captured leads = no lead slippage during onboarding
- WhatsApp delivery receipts provide confirmation that Pakistan's email infrastructure cannot
- aha-moment is observable and measurable (WhatsApp message received → contact created → deal tracked)

**Negative / Trade-offs:**
- WhatsApp API rate limits and webhook reliability are outside our control
- Conversation intent detection is probabilistic — requires confidence scoring + fallback to manual classification
- WhatsApp Business API onboarding (Meta approval) is a prerequisite with external lead time
- Sandbox→production transition requires additional verification (spec: `activation-model.md`)

**Mitigation:**
- Multiple provider adapters (360dialog, Gupshup, Meta direct) ensure no single provider lock-in
- Intent detection with explicit fallback: unclassified messages → human review queue
- `DUMMY_MODE: true` in `crm-api.js` allows full frontend development without live WhatsApp
